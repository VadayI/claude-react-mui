# План: усунення класу багів «обрізання файлів»

> Статус: **план** (виявлено й локально виправлено 2 випадки; системного захисту ще немає).
> Дата: 2026-06-03. Внесення змін — напряму, без PR (обслуговування шаблону).

## Проблема

Інструмент Edit/Write, що працює через Windows-шлях на mount, **мовчки обрізає файли**: файл закінчується посеред слова, без переносу рядка в кінці, втрачаючи «хвіст».

## Докази (цей сеанс)

- `CLAUDE.md` — обрізаний на «…scaffolds the Vite+M» у секції _Project bootstrap & preflight_ (з'явилось у `9dde1fc`; у `19934dc` ще ціле).
- `docs/WORKLOG.md` — робоче дерево обрізане на «- Tests: Vitest», втрачено 10 рядків проти HEAD (чисте видалення).
- Згадка в WORKLOG 2026-06-02: Edit через Windows-шлях уже раз обрізав `frontend-ci.yml` (крок _Upload Playwright report_ втратив `with:`).

## Гіпотеза root cause

Обидва обрізані файли містять багатобайтні UTF-8 символи (`→`, `·`, `—`) до точки обриву. Імовірний механізм — **розбіжність довжини в байтах vs символах**: інструмент рахує позицію в одних одиницях, а пише в інших, відрізаючи хвіст після останнього багатобайтного блоку. Додатковий фактор — конкуренція за `index.lock` / часткові записи при одночасному доступі VS Code.

## Заходи

1. **Записи лише через bash** (heredoc / redirection) для `.claude/**`, `docs/**` і кореня репо — перевірено надійно цього сеансу. Уникати Edit/Write на цьому mount.
2. **Гейт цілісності** `scripts/check_truncation.sh` — сканує версіоновані текстові файли на: (а) відсутній перенос рядка в кінці, (б) NUL-байти. Дешево ловить саме цей клас. Стиль — як наявні гейт-скрипти (`set -uo pipefail`, лог-префікс `[check_truncation] OK|FAIL|SKIP`, exit 0/1). Виключення для бінарних (png/jpg/woff/ttf/ico). Mid-word-обрив — лише NOTE, не FAIL (шумно).
3. **Wiring**: крок у `frontend-ci.yml` (джоб `quality`, після наявних гейтів), ціль у `Makefile` (`gates:`), рядок у `.claude/rules/node-commands.md`.
4. **Урок** у `docs/lessons.md`: «Edit-on-mount обрізає UTF-8 файли — пиши через bash; гейт ловить хвіст».

## Критерії приймання

- `scripts/check_truncation.sh` існує: FAIL на файлі без переносу рядка / з NUL, SKIP на бінарних, OK на чистому дереві.
- Інтегровано в CI і `make gates`.
- Додано запис у `lessons.md`.

## Ризики / відкрите

- Евристика «обрив посеред слова» шумна (багато коду легітимно не закінчується крапкою) → у v1 покладаємось на «немає переносу рядка + NUL»; mid-word лишити як NOTE.
- Першопричину в самому Edit-інструменті ми полагодити не можемо (це інструмент середовища) — гейт + дисципліна bash-записів компенсують.
