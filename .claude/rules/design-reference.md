# Design reference — Claude-design prototype as the UI source of truth

When a project has a **Claude-design prototype** (a functional HTML/JSX folder generated by Claude's design mode), it is the **strongest available UI source of truth** and UI agents must work from it. This rule defines what a prototype is, how it is discovered, what its authority means in practice, and how deviations are recorded.

## What a Claude-design prototype is

A Claude-design prototype lives under `docs/design/<name>/` and typically contains:

- **Design tokens** — CSS custom properties (e.g. `--c-accent`, `--c-bg`, `--font-body`) defining the colour palette, typography scale, spacing, radius, and shadow values.
- **UI-kit primitives** — a `ui-kit.jsx` (or similar) assembling buttons, inputs, cards, badges, and other atoms from the tokens.
- **Screens** — `screen-*.jsx` files (or named equivalents) each representing a distinct application screen: layout, content hierarchy, component placement, interactive states.
- **Data models** — an `app-data.jsx` (or similar) declaring the shape of entities the UI consumes.
- **API spec** — one or more `api-*.md` files describing the backend endpoints the prototype assumes.

The prototype is built for in-browser Babel / plain HTML. Its implementation style (inline styles, no TypeScript, no module imports) is **irrelevant to UI agents**. What matters is the **design intent**: colour palette, typography, spacing, component inventory, screen layouts, density, and interaction states.

## Detection and discovery

`/synthesize-brief` scans `docs/design/` for prototype signatures: subdirectories containing `index.html` + `*.jsx` / `screen-*` / `ui-kit`, and/or `api-*.md`. Detected candidates are shown to the user via `AskUserQuestion`; the user confirms the folder (if any) to use as the design reference. The confirmed path is recorded in `docs/PROJECT.md` § **Design reference** and passed to `brief-synthesizer`.

If no prototype is found or the user declines, UI agents work from MUI defaults and the written brief alone.

## Authority: very strong recommendation, adapted to the stack

The design reference is a **very strong source of truth for UI decisions** — not a pixel-perfect mandate. UI agents must:

- **Translate tokens → MUI theme.** CSS custom properties become `palette`, `typography`, `spacing`, and `shape` entries in `src/theme/`. The theme is the single source of design-token truth in production; no inline styles copying the prototype's CSS variables approach.
- **Translate ui-kit primitives → MUI components.** Prototype atoms (button variants, card structures, badge shapes) are realised through MUI component composition and `styleOverrides` in the theme — not by porting JSX verbatim.
- **Translate screens → routes + component tree.** Each screen maps to a route/screen in `src/features/<feature>/` with the same layout, content hierarchy, and interactive states — built with React 18 + TypeScript + TanStack Query + Zustand, following the feature-sliced structure in `@.claude/rules/architecture.md`.
- **Reproduce density, layout rhythm, and interaction states** as closely as the stack allows (loading skeletons, empty states, hover/active/focus styles from the prototype's intent, not literal CSS).

The prototype's **in-browser Babel / inline-style implementation is not copied**. Reproduce the _design intent_, not the implementation approach.

## Deviations — recorded, respected over the prototype

Any intentional difference between the produced UI and the design reference is a **deviation**. Deviations arise from:

- Explicit user instruction ("use a sidebar instead of bottom nav").
- Accessibility requirements (`@.claude/rules/accessibility.md`) — where the prototype would fail WCAG 2.1 AA, the accessible version wins and the departure is recorded.
- Component-contract requirements (`@.claude/rules/component-contract.md`) — the four mandatory states (loading/success/empty/error) win over a prototype that only shows the happy path.
- Technical constraints (e.g. a prototype animation that conflicts with `prefers-reduced-motion`).

Every deviation is recorded in **two places**:

1. **Project memory** (type `project`) — one entry per deviation, with the reason.
2. **`docs/PROJECT.md` § "Design deviations"** — a human-readable list that survives context resets and is visible in the PR diff.

Agents read recorded deviations **before** consulting the prototype; deviations override the design reference.

## Priority order (when conflicts arise)

1. Recorded deviations (explicit user overrides).
2. Accessibility requirements (`@.claude/rules/accessibility.md`).
3. Component-contract requirements (four states, `@.claude/rules/component-contract.md`).
4. The design reference (prototype intent).
5. MUI defaults.

When a conflict between items 2/3 and item 4 is resolved, the resolution is appended to the deviation list with the reason (e.g. "prototype lacked loading state — added skeleton per component-contract").

## Binds these agents (rule is auto-loaded)

- `brief-synthesizer` — reads the confirmed design folder as a first-class input; extracts token summary, component inventory, screen list, and API assumptions; produces **Design reference** and **Design deviations** sections in `docs/PROJECT.md`.
- `ui-architect` — reads the **Design reference** section in `docs/PROJECT.md` and maps tokens → MUI theme entries, screens → route/component tree, respecting the **Design deviations** list. Records any new conflict-resolution deviation.
- `react-developer` — implements components following the MUI theme derived from design tokens; reproduces screen layouts from the prototype; never copies prototype inline styles. Flags any new deviation to the orchestrator for recording.
- `reviewer` — blocks UI code that silently diverges from the design reference without a recorded deviation. A visual gap not in the deviation list is 🟡 Important.

> Goal: the design reference is a first-class input — faithfully reproduced under MUI/TypeScript, transparently deviated from when accessibility, contract, or user intent demands it, and never silently ignored.
